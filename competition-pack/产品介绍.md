# 鲁品开拍 · 产品介绍

## 一句话介绍

「鲁品开拍」是面向山东农产品经营者的 AI 短视频拍摄方案工具：把产品信息和真实拍摄条件，转化为一份可执行、可编辑、可约束的拍摄执行单。

## 目标用户

- 山东本地农产品、食品、特色产品的经营者（农户、合作社、小商户）
- 没有专业拍摄团队、只有手机和 1-2 个人手的创作者
- 想做短视频带货，但不知道"拍什么、怎么拍、说什么"的用户

## 具体问题与使用场景

**问题**：农产品商家想拍短视频宣传，但面临三个困难：
1. 不知道拍什么内容（缺创意）
2. 即使有想法，也组织不成可执行的分镜（缺结构）
3. 拍出来的文案容易踩宣传红线（极限词、功效宣称），自己意识不到（缺风险意识）

**使用场景**：章丘大葱种植户老王，只有 1 部手机、1 个人，想在菜地里拍一条 45 秒的带货视频。他打开「鲁品开拍」，填写"章丘大葱、葱白长甜脆、目标家庭主妇、手机单人、菜地、45秒"，拿到 3 个创意方向，选定后得到 7 个镜头的完整拍摄方案，检查风险后导出一份 Word 执行单，照着拍就行。

## 产品解决问题的完整流程

1. **填写产品信息和拍摄条件**：产品名称、卖点、目标受众、价格、证明材料，以及拍摄设备、人数、场景、目标时长
2. **生成 3 个视频创意**：AI 基于产品信息生成 3 个差异化创意方向（含创意点、开场3秒、拍摄难度）
3. **生成结构化分镜**：选定方向后，生成带镜头序号、时长、景别、画面描述、拍摄动作、运镜、旁白、字幕、道具、素材的完整分镜；Pydantic 结构校验 + 业务规则校验（总时长误差≤2秒、单人手机约束），不通过自动重试最多 3 次
4. **编辑、锁定、重生成**：可编辑任意镜头；锁定满意的镜头后，重生成其他镜头时锁定内容逐字段保护不被覆盖
5. **宣传风险检查**：三层——规则初检（极限词/销量/功效/认证关键词库）+ 模型复核（委婉功效暗示）+ 人工确认（逐条勾选）
6. **导出 DOCX**：总时长校验通过 + 风险项全部人工确认后，导出带分镜表、素材清单、风险提示的 Word 执行单

## 相比普通 AI 文案生成工具的差异

| 维度 | 普通 AI 文案工具 | 鲁品开拍 |
|------|-----------------|---------|
| 输出 | 一段营销文案 | 结构化分镜（镜头/时长/动作/口播/字幕/道具） |
| 约束 | 无 | 真实拍摄条件约束（单人手机拍不了航拍，自动拦截） |
| 可编辑性 | 重新生成整段 | 单镜头编辑、锁定、重生成，锁定保护 |
| 时长 | 不管 | 总时长精确校验（误差≤2秒），不符禁止导出 |
| 风险 | 无 | 三层风险检查，未经证实的"销量第一""降血压"被隔离 |
| 交付 | 复制粘贴 | 一键导出 Word 拍摄执行单 |

**核心价值**：不是生成一段文案，而是把 AI 生成的内容转化为**可执行、可编辑、可约束**的拍摄方案。

## 当前已实现的功能

- [x] 产品信息表单（含拍摄条件：设备/人数/场景/时长）
- [x] 3 个创意方向生成（AI，温度 0.7）
- [x] 结构化分镜生成（AI + Pydantic 校验 + 最多 3 次重试）
- [x] 分镜编辑器：编辑/删除/上移/下移/锁定/单镜重生成
- [x] 锁定镜头保护（重生成时逐字段比对，意外改动则中止）
- [x] 总时长校验（误差≤2秒，导出前强制检查）
- [x] 三层风险检查（规则初检 + 模型复核 + 人工确认）
- [x] DOCX 导出（分镜表/素材清单/风险提示/待确认事项）
- [x] 单人手机拍摄约束检查（航拍/摇臂等不可行方式自动拦截）

## 技术方案及选择理由

| 选择 | 方案 | 理由 |
|------|------|------|
| 后端 | FastAPI + Pydantic | 结构化输出需要强校验；Pydantic 模型即文档 |
| 前端 | 原生 HTML/JS/CSS | 单页工具，无需框架；部署零依赖 |
| AI 调用 | 独立 AIService 层 | 调用/重试/错误映射/token 记录集中管理；参考 ai-policy-assistance 的独立服务层设计 |
| 校验 | Pydantic + 业务规则 + 最多 3 次回填重试 | 模型输出不可靠，必须"生成→校验→回填错误→重试"闭环 |
| 风险 | 规则关键词库 + 模型复核 + 人工确认 | 规则抓不住委婉暗示，模型可能误报，人工是最后一道闸 |
| 导出 | python-docx | Word 是农户/商户最熟悉的文档格式 |
| 持久化 | 无（内存状态） | MVP 阶段不需要数据库；需要时再上 SQLite |

**不做的**：多智能体框架、向量数据库/RAG、自动视频生成、账号/登录/付费、云端部署——这些与"可执行的拍摄方案"核心价值无关。

## 目前的限制（诚实说明）

- 模型依赖第三方 API（deepkey 中转 gpt-6-luna），网络波动或 API 不可用时生成功能不可用
- 模型单次响应偶尔需要 45 秒以上，极端情况下可能接近 120 秒超时
- 风险检查是"初步提示"，不是法律审查或广告合规保证
- 未做用户数量统计，无商业化成果，无实际经营效果数据——以上均不声称
- 浏览器兼容性：已在 Firefox 验证通过；Chrome 142+ 访问本地服务会被其本地网络检查拦截（浏览器自身限制，非产品问题）
- 删除镜头后需手动调整其他镜头时长以满足总时长要求（暂无一键补齐）
