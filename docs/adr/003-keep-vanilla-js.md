# ADR-003：原生 JS 暂不迁移框架

- 状态：已采纳
- 日期：2026-10-17
- 相关：221-240（前端组）

## 背景

前端为原生 HTML/CSS/JS（`frontend/js/` 按业务拆 10 模块）。
企业级路线曾提议迁移 Vue 3 + TypeScript。

## 决策

**分三阶段，当前停在第一阶段**：

1. **第一阶段（当前）**：保留原生 JS，优先修状态管理缺陷
   （统一修改入口、保存状态反馈、失败恢复 —— 221-223）。
2. **第二阶段**：按组件化思路重组现有模块（store/views/components 目录）。
3. **第三阶段**：仅当实时协作、复杂时间轴等需求使维护成本显著上升时，
   再评估迁移 Vue 3 + TypeScript。

## 理由

- 当前页面以表单 + 列表为主，无复杂交互，框架收益 < 迁移成本。
- 团队主力为后端，前端人力有限；重写风险高于渐进改良。
- 原生 JS 的首屏加载与 CloudBase 冷启动更友好。

## 备选方案

1. **立即迁 Vue 3**：重写 10 个 JS 模块 + 测试，2-3 周工作量，
   且大赛截止 11-20 前必须稳定。否决。
2. **React**：同上，且与现有 CSS 体系耦合更深。否决。

## 后果

- 正面：零构建步骤，部署即 `StaticFiles` 托管；调试直观。
- 负面：状态分散问题需靠纪律（统一修改入口）而非框架约束。
- 缓解：`frontend/js/core.js` 为唯一状态出口；新增模块按 Checklist 走。

## 复评触发条件

- 出现实时协作（多用户同作品编辑），或
- 单文件 JS 超 1500 行且拆分后仍难维护。

任一触发即重开本 ADR 评估。
